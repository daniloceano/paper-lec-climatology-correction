# Repository rules for the post-publication correction

## Immutable published baseline

- `LEC_climatology_clim_dyn_vCBG/sn-article_rev2.tex` is the authoritative published-manuscript baseline.
- Never modify, reformat, rename, overwrite, or regenerate that file.
- Treat the other files in the original Overleaf package as read-only unless an author explicitly authorizes a specific change.
- Do not assume that `sn-article.tex`, `sn-article_rev1.tex`, or another intermediate file is authoritative.
- Before and after correction work, compare the SHA-256 checksum of the baseline with the value recorded in `SCIENTIFIC_SOURCES.md`.

## Scientific source of truth

- Corrected scientific values come exclusively from `lec-climatology-rerun` at the audited commit recorded in `SCIENTIFIC_SOURCES.md` and from the pinned LorenzCycleToolKit correction.
- The production toolkit commit is `d38cda7e37d8e8a3a937a5919640a94bef19e34a`; it contains scientific correction commit `d07707767c2962fed0475ff4573e7d15a97f8c69`.
- Do not invent, smooth, rescale, reinterpret, or visually estimate corrected values when a machine-readable result exists.
- Do not recompute the LEC in this manuscript repository.

## Separation of roles

This repository owns:

- the Correction manuscript;
- the textual impact assessment;
- replacement-figure selection;
- editorial material;
- the human-readable manuscript difference.

`lec-climatology-rerun` owns:

- scientific computation and validation;
- corrected datasets and statistics;
- scientific figures;
- computational provenance.

## Traceability

Every substantive scientific manuscript change must have an entry in `CORRECTION_MATRIX.md` that records:

1. the published location;
2. the original claim or value;
3. the corrected evidence;
4. the exact scientific source path;
5. the required editorial action;
6. confidence and status.

Do not merge a scientific edit that lacks a matrix entry.

## Minimal correction

- Preserve wording that remains scientifically valid.
- Do not rewrite prose merely for style.
- Change only incorrect material and the minimum surrounding text needed for coherence.
- Preserve the Springer Nature class, labels, citations, bibliography, section organization, and figure numbering where feasible.

## Author control of manuscript prose

- Do not autonomously rewrite `LEC_climatology_clim_dyn_vCBG/sn-article_correction.tex`.
- Agents may audit the manuscript, propose exact patches for author review, update `CORRECTION_MATRIX.md`, regenerate `sn-article_correction_diff.tex`, and validate compilation.
- Manuscript prose, equations, tables, captions, and scientific content may be changed only after explicit author instruction for that change.
- Infrastructure-only authorization does not authorize manuscript edits.

## Uncertainty and conflicts

- Never guess when evidence is incomplete or conflicting.
- Add a `BLOCKED` or `NEEDS_AUTHOR_REVIEW` matrix item and state exactly what is missing.
- In the LaTeX source, use a nearby comment beginning `% CORRECTION-BLOCKED:` for unresolved material.
- Do not silently resolve competing workflow versions.

## Figures

- Never edit numerical or scientific content inside a figure by hand.
- Corrected figures must originate in `lec-climatology-rerun`.
- A copied figure must record its source path, source Git commit, destination path, and checksum in `SCIENTIFIC_SOURCES.md` or `CORRECTION_MATRIX.md`.
- A before/after audit graphic is not automatically a publication-ready corrected-only replacement.

## Compilation and generated files

- `sn-article_correction.tex` is the clean working correction manuscript.
- `sn-article_correction_diff.tex` is generated by `scripts/build_diff.sh`; never maintain it independently.
- Both manuscripts must compile successfully before a correction pass is considered complete.
- Bibliography and cross-references must resolve, and the visual diff must show deletions in red with strikethrough and additions in blue.

## Version-control safety

- This is an active Git checkout of `daniloceano/paper-lec-climatology-correction`; use both Git status and the recorded SHA-256 checksum to verify baseline immutability.
- Do not commit, push, pull, or synchronize with Overleaf autonomously. Perform each GitHub/Overleaf synchronization only in an explicit author/agent turn.
- Before a requested commit or push, show the relevant diff, compiled validation, and repository status for author review.
